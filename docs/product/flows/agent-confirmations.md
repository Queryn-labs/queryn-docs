# Агентный ход с подтверждениями

В desktop реализован диалоговый вызов агента <code>chatAgent</code>. Пользователь
создаёт сессию, пишет цель и выбирает поставщика с моделью. Renderer показывает
поток ответа и активности, а для облачного поставщика и рискованной операции
останавливает продолжение до решения пользователя. Отдельного редактора плана
с фазами планирования и исполнения в текущем интерфейсе нет.

## Поток

~~~mermaid
flowchart TD
  Session["SessionWorkspace"] --> Goal["Новая сессия: цель"]
  Goal --> Save["appendSessionEvent: user-message"]
  Save --> Model{"Поставщик и модель выбраны?"}
  Model -->|нет| Stored["Цель сохранена, ответ не запускается"]
  Model -->|локальный| Chat["chatAgent"]
  Model -->|облачный| Cloud["Предупреждение: контекст уйдёт внешнему серверу"]
  Cloud --> Preview["Проверить: открыть read-only preview контекста"]
  Cloud -->|Разрешить один раз| Chat
  Chat --> Stream["agent.output.delta + agent.activity"]
  Stream --> Tool{"Рискованная операция?"}
  Tool -->|нет| Final["Завершение чата и события сессии"]
  Tool -->|да| Wait["waiting-approval"]
  Wait --> Decision["approveAgentChatRun: разрешить один раз"]
  Decision -->|разрешено| Stream
  Stream --> Result["Артефакты и результат"]
  Stream --> Stop["Отмена: cancelAgentChat(requestId)"]
  Stop --> Cancelled["Состояние cancelled"]
~~~

В облачном ветвлении кнопка проверки открывает уже загруженный
<code>previewContext</code>. Это просмотр источников, а не редактор состава
контекста. Composer не принимает произвольные вложения и не предлагает
выбор файлов для отправки.

## Точки потока

| Точка | Экран/действие | Ошибка/деградация |
| --- | --- | --- |
| Сессия | <code>NewSessionSheet</code> создаёт сессию с заголовком из цели через <code>createSession</code> | Без активной сессии отправить сообщение нельзя |
| Сообщение | Composer сохраняет текст через <code>appendSessionEvent</code> | Если интеллект выключен, показывается предложение включить его в настройках |
| Модель | Выбор модели и поставщика хранится в настройках приложения | При пустом выборе цель сохраняется, но вызов агента не выполняется |
| Облако | Перед вызовом показывается получатель и доступны <code>Проверить</code> и <code>Разрешить один раз</code> | Отдельного постоянного разрешения в этом экране нет; без разрешения вызов не продолжается |
| Запуск | <code>chatAgent({ projectId, sessionId, goal, providerId, model, requestId })</code> | Ошибка runtime или модели переводит экран в ошибочное состояние |
| Ответ | Потоковые события обновляют текст и трассу активностей | Сбой трассы помечается, а основной ответ может быть показан отдельно |
| Действие агента | История показывает вызовы операций и наблюдения | Отдельного экрана плана или ручной стадии Execute нет |
| Подтверждение | Для <code>pendingJobId</code> кнопка вызывает <code>approveAgentChatRun</code> с областью <code>once</code> | Кнопки отказа в текущем интерфейсе нет; ожидание остаётся до разрешения или сбоя |
| Остановка | Кнопка остановки вызывает <code>cancelAgentChat</code> для активного запроса | Прерванный ответ получает состояние <code>cancelled</code> |
| Результат | Связанные с событиями артефакты показываются в секции результатов и открываются через проект | Composer не умеет прикреплять произвольный артефакт к новому сообщению |
| Повторный вход | При открытии сессии renderer читает события и последний запуск через <code>getAgentChatRun</code> | Видимой кнопки для <code>resumeAgentChatRun</code> нет |

## Граница реализации

Фактическая модель этого потока — одна цель, один вызов чата и возможные
вызовы операций внутри него. Формулировки про самостоятельный план,
отдельное исполнение, выбор вложений и отказ не следует трактовать как
реализованные возможности этой версии.
