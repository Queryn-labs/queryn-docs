# Шаблон ADR

Используйте этот шаблон для решения, которое меняет долгосрочную продуктовую,
архитектурную или межрепозиторную границу Osnova.

## Фронтматтер

```yaml
---
authority: normative
lifecycle: active
adrStatus: accepted
---
```

Для решения, которое заменено новой ADR, укажите стабильный номер новой страницы:

```yaml
adrStatus: superseded
supersededBy: 14
```

Допустимые значения `adrStatus` — `accepted`, `superseded` и `rejected`. Поле
`supersededBy` используется только при значении `superseded` и должно указывать
на существующую ADR со статусом `accepted`.

## Имя и структура файла

Имя файла имеет вид `adr-NNNN-kebab-slug.md`. Номер получает следующая свободная
позиция журнала, а путь после публикации не меняется.

```markdown
# ADR NNNN: Короткое название

## Статус

Принято.

## Контекст

Какая проблема и какие ограничения требуют решения.

## Решение

Что именно принимается и какая граница считается обязательной.

## Последствия

Какие изменения, ограничения и следующие действия появляются.
```

Статус в тексте помогает читателю, но автоматические проверки используют только
поля YAML. Если решение заменено, не переносите старую страницу в архив и не
меняйте её имя ради отражения нового статуса.
