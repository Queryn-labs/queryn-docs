# ADR 0010: Агент и risk policy

## Статус

Принято.

## Решение

Агентный запрос выполняется единым диалоговым tool-loop `AgentKernel`, который
запускается через `agent.chat`. На каждом шаге ядро передаёт модели историю
текущей сессии и схемы доступных зарегистрированных operations, принимает текст
и вызовы operations, исполняет вызовы через Job Manager и возвращает итоговый
текстовый ответ. Запуск ограничен host-enforced `maxSteps` и
`maxDurationSeconds`.

Текущий контракт не содержит отдельного структурного `AgentPlan`, pipeline или
жизненного цикла `agent.plan`, `agent.execute`, `agent.approve` и
`agent.cancel`. Методы `agent.chat.get`, `agent.chat.resume`,
`agent.chat.cancel` и `agent.chat.approve` управляют текущим диалоговым
запуском. `agent.chat.approve` подтверждает ожидающий вызов операции и не
является подтверждением заранее составленного плана.

Каждый вызов operation проходит проверку регистрации, доступности в проекте,
разрешений и risk policy. Для расширений runtime сопоставляет объявленные
permissions с project grants. Для встроенных и MCP-операций применяется
проверка риска. Операции с network egress, внешним эффектом или повышенными
правами при отсутствии сохранённого project-scoped правила переводят job в
`waiting-approval`. Пользователь принимает решение для конкретного вызова
один раз или сохраняет разрешение для этой operation и проекта, после чего
диалоговый цикл продолжается.

## Последствия

Plugin permission не означает безусловную автономность. Сессия сохраняет
видимые сообщения, вызовы tool и operation, наблюдения, approvals, результаты и
ссылки на созданные артефакты, но не скрытые рассуждения модели и не отдельный
AgentPlan.

В текущем `ChatRun` и финальном `assistant-message` нет структурированного поля
`sources`. Контекстный preview может показать источники до запуска, но итоговый
ответ не является ответом с встроенным списком источников. Полная атрибуция
источников в финальном ответе остаётся будущим изменением контракта.
