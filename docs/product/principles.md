# Принципы продукта

## Local first

Папка проекта является источником истины. Osnova не должна требовать удаленную учетную запись для создания, открытия или редактирования проекта.

## Обычные файлы

Конспекты хранятся в Markdown. Файлы проекта являются обычными файлами. Метаданные хранятся в JSON. Пользователь и внешние инструменты должны иметь возможность просматривать проект без desktop-клиента.

## Стабильные контракты

Общее поведение должно находиться в `osnova-spec` и `osnova-core`, а не только в desktop-приложении.

## Расширяемость

Расширения имеют явные manifests, contributions, permissions и runtime. Они
объединяются через операции и типизированные артефакты, а не через доступ к
внутренностям приложения.

## AI опционален

AI-функции должны улучшать рабочие процессы, но не делать владение локальным проектом зависимым от model runtime.

## Manual first

Предметный инструмент должен быть полезен без агента. В текущем runtime ручной и
агентный запуск доступных operations используют один Job Manager и одну модель
артефактов. В desktop кодовый `ToolWorkspace` пока не имеет доступного маршрута
из `ProjectNavigator`, поэтому ручной пользовательский вход в operation flow
остаётся целевой возможностью. Отдельный manual view для каждого расширения не
является общим реализованным контрактом.

## Artifacts first

Результаты, созданные и опубликованные operation flow, имеют тип, переносимый
payload и происхождение. Нативные notes и assets остаются обычными файлами без
ArtifactDescriptor и provenance операции. Runtime caches не считаются
результатами и могут быть удалены.

## Inspectable context

Текущий desktop показывает в preview контекста оценку объёма, получателей и до
восьми источников. Это не гарантирует точное отображение фактически отправленного
запроса и не заменяет выбор или прикрепление материалов. Неизвестный тип данных
не отправляется модели без явного context provider. Полная инспекция отправляемого
контекста является будущим развитием.

## Explicit risk

Permissions пакета не заменяют подтверждение конкретного рискованного действия.
В текущем runtime вызов operation проходит risk policy, а network egress,
внешний эффект и привилегированные операции могут приостановить job до
per-operation approval. Настройка разрешений в интерфейсе Tool Manager ещё не
разделяет каждое permission отдельным выбором пользователя.

## Graceful degradation

Проект открывается при отсутствии расширения, модели, OCI runtime или сети.
Недоступная возможность диагностируется, но не блокирует остальные материалы.
