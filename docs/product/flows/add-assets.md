# Добавление файлов в проект

Файлы пользователя копируются в область <code>assets/</code> открытого проекта.
В desktop-потоке это drag and drop на поверхность материалов или на каталог в
дереве. Файл не становится ссылкой на исходный путь: <code>importAsset</code>
создаёт копию внутри проекта.

Поток реализован в <code>MaterialsWorkspace</code>,
<code>useProjectMaterials</code> и <code>AssetViewer</code>.

## Поток

~~~mermaid
flowchart TD
  Project([Открытый проект]) --> Materials["Режим Проект"]
  Materials --> Drop["Перетащить файл"]
  Drop --> Path["Получить native path"]
  Path --> Import["importAsset"]
  Import --> Copy["Скопировать в assets/"]
  Copy --> Unique["Выбрать уникальное имя"]
  Unique --> Refresh["Обновить дерево материалов"]
  Refresh --> Asset["Выбрать файл"]
  Asset --> Viewer["AssetViewer"]
  Viewer --> Image{"Тип image/*?"}
  Image -->|да| Preview["Показать изображение"]
  Image -->|нет| Meta["Показать тип и размер"]
  Meta --> External["Открыть во внешнем приложении"]
  Preview --> External
  Import -->|ошибка пути или копирования| Error["Сообщение об ошибке"]
~~~

Путь берётся из <code>File.path</code>, а при его отсутствии — через
<code>webUtils.getPathForFile</code>. Целевая папка определяется выбранным
каталогом или каталогом, на который выполнено перетаскивание. Если имя уже
занято, core выбирает уникальный путь, поэтому исходный файл не перезаписывается.

Если во время добавления открыт конспект, desktop вставляет в его черновик
обычную Markdown-ссылку на путь внутри каталога <code>assets/</code> и помечает конспект
как несохранённый. Сам импорт файла и сохранение изменённого конспекта остаются
разными действиями.

## Точки потока

| Точка | Экран/действие | Ошибка/деградация |
| --- | --- | --- |
| Вход | Открыть <code>Проект</code> и выбрать каталог в дереве или поверхность материалов | Пустой проект показывает состояние без материалов |
| Перетаскивание | <code>MaterialsWorkspace</code> показывает зону <code>Добавить файлы в проект</code> | Событие без файлов не запускает импорт |
| Получение пути | <code>getPathForFile</code> нормализует объект <code>File</code> Electron | Если native path недоступен, показывается <code>Не удалось получить путь к файлу.</code> |
| Импорт | <code>importAsset</code> копирует каждый файл в <code>assets/</code> | Ошибка чтения исходного файла или копирования показывается сообщением |
| Повторное имя | Core создаёт уникальный путь | Файл не заменяет существующий, пользователь получает новый путь |
| Связь с конспектом | В активный черновик добавляются Markdown-ссылки | Ссылки остаются несохранёнными до отдельного сохранения конспекта |
| Просмотр | Для <code>image/*</code> доступен локальный preview, для остальных — метаданные | Для неизвестного или бинарного типа preview не обещается |
| Внешний файл | <code>openExternalFile</code> открывает проектный путь системой | Ошибка внешнего приложения показывает сообщение desktop |

## Граница реализации

Импорт не удаляет исходный файл, не загружает его в сеть и не создаёт
полноценный редактор PDF или аудио. Просмотр изображения выполняется внутри
desktop, остальные типы передаются внешнему приложению.
