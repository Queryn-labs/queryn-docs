# ADR 0011: Кросс-сессионная память агента

## Статус

Принято.

## Контекст

Сессии в проекте Osnova хранятся как журналы (`sessions/<id>/events.jsonl`), а базой
знаний остаются артефакты и заметки. При этом агент не видел ничего из прошлых
диалогов, поэтому пользователю приходилось заново объяснять контекст или вручную
переносить выводы в заметки. Полный автоматический доступ к прошлым сессиям
нежелателен: содержимое диалогов может быть личным, и его раскрытие модельному
контексту должно быть осознанным решением пользователя.

## Решение

Каталог прошлых сессий (заголовок, идентификатор, дата, последние 10 записей)
виден агенту всегда: он дёшев и не раскрывает содержимое диалогов.

Доступ к содержимому прошлых сессий — опт-ин «Полная память» на уровне отдельной
сессии. Режим хранится в `SessionDescriptor.memoryMode`. Реализация — жёсткий гейт
набора инструментов рантайма, а не промпт-просьба: без включённого режима операции
`osnova.session.search` и `osnova.session.read` вообще отсутствуют в схемах
инструментов агента. Выключение режима действует со следующего шага прогона,
поскольку события и схемы инструментов перечитываются на каждой итерации.

Приватность: без включённой галочки ни один путь рантайма не отдаёт модельному
контексту содержимое чужих сессий. Новые сессии создаются с выключенной памятью.

Будущее развитие: суммаризация завершённых сессий в артефакты, которые автоматически
индексируются ContextBroker. Направление зафиксировано, но не реализовано.

## Последствия

Агент отвечает на вопросы о прошлых диалогах только в сессиях с включённой полной
памятью. Переключение режима доступно из шапки сессии и вступает в силу без
перезапуска приложения. Журналы сессий остаются производными данными по ADR 0006:
включение памяти не меняет их статус и правила переноса.
