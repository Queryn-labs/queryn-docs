# Настройки, палитра и пользовательский CSS

Настройки приложения открываются из верхней панели <code>WorkspaceHome</code>.
В модальном окне есть разделы оформления, пользователя, Queryn Intelligence и
среды выполнения. Эта страница описывает только реализованные изменения
оформления. Палитра и CSS относятся к приложению целиком, а не к отдельному
проекту.

## Поток

~~~mermaid
flowchart TD
  Home["WorkspaceHome"] --> Settings["Настройки"]
  Settings --> Appearance["Оформление"]
  Appearance --> Theme["Тема: system / light / dark"]
  Appearance --> Palette["Одна из встроенных палитр"]
  Appearance --> CSS["Пользовательские стили"]
  Theme --> LocalTheme["localStorage: queryn-theme"]
  Palette --> SavePalette["settings.appearance.palette + local cache"]
  CSS --> Normalize{"Поле пустое?"}
  Normalize -->|нет| StoreCSS["settings.appearance.customCss"]
  Normalize -->|да| RemoveCSS["Удалить customCss"]
  StoreCSS --> Apply["Применить поверх токенов"]
  RemoveCSS --> Apply
  Apply --> App["Текущий desktop"]
  Settings --> Runtime["Среда выполнения: статус и диагностика"]
  Runtime -->|Проверить| Doctor["runDiagnostics"]
~~~

Тема записывается отдельным локальным механизмом, а палитра и пользовательский
CSS сохраняются через <code>writeSettings</code>. Если CSS состоит только из
переменных, renderer оборачивает его в <code>:root</code>; полноценные правила
CSS также принимаются. Изменения не записываются в папку проекта.

## Точки потока

| Точка | Экран/действие | Ошибка/деградация |
| --- | --- | --- |
| Открытие | Кнопка настроек в <code>WorkspaceHome</code> открывает раздел оформления; профиль открывает раздел пользователя | Если чтение настроек или runtime завершается ошибкой, показывается сообщение |
| Тема | Выбор <code>Системная</code>, <code>Светлая</code> или <code>Тёмная</code> вызывает <code>setThemeMode</code> | Тема хранится в localStorage текущего desktop, серверной или проектной синхронизации нет |
| Палитра | Выбор одной из семи встроенных палитр вызывает <code>setPaletteId</code> | Пользовательского редактора палитры нет; выбор действует на приложение |
| CSS | Ввод CSS и нажатие <code>Применить</code> вызывает <code>writeSettings</code> с <code>appearance.customCss</code> | Пустое поле удаляет CSS; синтаксическая проверка CSS в этом окне не заявлена |
| Применение | <code>useCustomTheme</code> применяет пользовательские правила после токенов | Ошибка записи не применяет новое значение; проектные файлы не меняются |
| Проекты | В том же разделе можно изменить папку проектов через <code>selectFolder</code> и <code>writeSettings</code> | Это базовая папка для новых проектов, уже созданные проекты не перемещаются |
| Диагностика | Раздел среды выполнения вызывает <code>runDiagnostics</code> и показывает JSON-отчёт | Диагностика не исправляет runtime и не настраивает палитру |

## Граница реализации

В коде есть модель <code>workspaceLayout</code> и чтение выбранного layout,
однако пользовательского редактора расположения виджетов нет. Стили,
профиль, тема и палитра не следует описывать как настройки, переносимые
между проектами.
