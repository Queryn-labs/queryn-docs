# ADR 0013: Сетевые инструменты агента

## Статус

Принято.

## Контекст

Агент работает в локальном проекте, но часть задач требует интернета: открыть
страницу по ссылке пользователя или выполнить поиск во внешнем поисковике.
Любой сетевой вызов — это исходящий трафик с содержимым запроса пользователя,
поэтому молчаливый доступ недопустим и должен проходить через существующую
систему рисков и подтверждений.

## Решение

Сетевой доступ предоставляется двумя механизмами поверх общей policy-машины:

1. Встроенная операция `osnova.web.fetch`: получает публичную http(s)-страницу
   по URL, сокращает её до читаемого текста с лимитами (таймаут, размер ответа,
   длина выдачи). Риск `network-egress`, разрешение `network:use`.
2. Внешние инструменты через MCP. Мост подключает локальные stdio-серверы;
   их инструменты регистрируются в общем реестре операций и по умолчанию имеют
   риск `external-side-effect`. Дескрипторы зарегистрированных серверов
   сохраняются в состоянии runtime (`mcp-servers.json`) и переподключаются при
   старте; удаление сервера убирает его инструменты.

Оба пути проходят одинаковый цикл: политика требует явного одобрения для
`network-egress` и `external-side-effect`, агент приостанавливается до решения
пользователя. Ключи доступа к внешним сервисам передаются в переменных
окружения сервера и хранятся в локальном состоянии runtime, не в папке проекта.

Поисковые провайдеры (например Exa) подключаются как MCP-серверы без отдельного
кода в рантайме: достаточно зарегистрировать сервер с ключом доступа.

## Последствия

Первое обращение агента к сети всегда требует решения пользователя; дальнейшая
политика может кешировать одобрение на проект. Бесплатные способы поиска через
скрейпинг отклонены как хрупкие и нарушающие условия использования — поиск
подключается провайдером с официальным API.
