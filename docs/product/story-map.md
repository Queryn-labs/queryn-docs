# Карта историй продукта

Карта разделяет то, что уже подтверждено кодом версии 0.2, и последующие
приоритеты. Колонка R1 описывает текущий факт, а R2 и R3 являются границами
работы и не означают, что соответствующий экран или API уже поставлены.

Ось backbone идёт слева направо: создать проект → собрать материал →
конспектировать → связывать → использовать инструменты → делегировать агенту
→ ревьюировать результаты → управлять инструментами и настройками.

## Уровни

| Уровень | Смысл |
| --- | --- |
| Базовый | Локальная папка проекта, материалы и ручная работа с Markdown |
| Регулярный | Повторяемые сессии, контекст проекта, операции и просмотр результатов |
| Продвинутый | Агентный цикл, расширения, политики разрешений, модели и фоновые сценарии |

Уровень показывает ширину пользовательской задачи. Он не превращает
компонент, который невозможно открыть из текущей навигации, в поставленную
функцию.

## Базовый уровень

| Backbone | R1 · реализовано в 0.2 | R2 · текущий цикл | R3 · следующее |
| --- | --- | --- | --- |
| Создать проект | <code>WorkspaceHome</code> создаёт проект из имени и родительской папки; существующую папку можно усыновить | Согласовать явный маршрут между созданием, усыновлением и первым материалом | Рабочий контекст вне одной папки проекта |
| Собрать материал | В режиме <code>Проект</code> создаются конспекты и каталоги, файлы импортируются в <code>assets/</code> копированием или перетаскиванием | Сделать состояние импорта и границы файлов заметнее в рабочем потоке | Opt-in синхронизация материалов, если появится поддержанный транспорт |
| Конспектировать | <code>NoteEditor</code> и <code>MarkdownEditor</code> создают, редактируют и сохраняют Markdown в <code>notes/</code> | Выстроить короткий повторяемый путь от материала к конспекту | Контекст вне проекта для работы с несколькими источниками |
| Связывать | <code>[[Название конспекта]]</code> связывает заметки, а Markdown-ссылка может вести на asset; отдельного графа нет | Улучшить обнаружение и ревью связей без обещания графового экрана | Межпроектные связи только после явной политики хранения и доступа |
| Использовать инструменты | Runtime регистрирует встроенные операции, но ручной <code>ToolWorkspace</code> не имеет доступного входа из <code>ProjectNavigator</code> | Подключить проверяемый пользовательский маршрут к ручной операции и её результату | Расширить ручную работу за пределы одного проекта при сохранении политики |
| Делегировать агенту | В сессии можно отправить текстовую цель в <code>chatAgent</code>; произвольные вложения и отдельный план/Execute отсутствуют | Зафиксировать границы цели, контекста и ответа в одном понятном сценарии | Контекст рабочей области вне проекта и фоновая обработка |
| Ревьюировать результаты | Timeline сессии показывает сообщения, активности и связанные артефакты; результат можно открыть или форкнуть | Связать ревью с понятным статусом задания и источниками контекста | Возобновляемая фоновая обработка с журналом изменений |
| Управлять инструментами и настройками | Настройки открываются из <code>WorkspaceHome</code>, тема, палитра и CSS сохраняются локально; редактора layout нет | Явно показать состояние доступных инструментов и ограничений настроек | Подписанный каталог и безопасный opt-in поток синхронизации |

## Регулярный уровень

| Backbone | R1 · реализовано в 0.2 | R2 · текущий цикл | R3 · следующее |
| --- | --- | --- | --- |
| Создать проект | Проект после создания открывается в режиме <code>Сессия</code>, повторный вход идёт через список недавних проектов | Уточнить переход от проекта к повторяемому рабочему циклу | Единый рабочий контекст поверх нескольких проектов |
| Собрать материал | Дерево показывает notes/assets, поддерживает каталоги, перенос и открытие локальных файлов | Согласовать представление материалов и артефактов в одном ревью | Opt-in синхронизация с явным источником и политикой |
| Конспектировать | Сохранение документа обновляет заголовок, тело и временные поля Markdown-файла | Уменьшить разрыв между ручным конспектом и результатом операции | Контекстные провайдеры для внешних источников после политики доступа |
| Связывать | <code>listProjectLinks</code> возвращает найденные связи внутри проекта; переход по asset использует обычный путь файла | Сделать ошибки неразрешённых ссылок видимыми, не добавляя отсутствующий граф | Рабочие связи между источниками с контролем области видимости |
| Использовать инструменты | <code>listOperations</code> и <code>invokeOperation</code> доступны runtime и preload; пользовательский экран запуска сейчас недостижим | Довести до экрана только операции, их схемы, задания и подтверждения, которые реально поддерживает runtime | Подписанный каталог и расширяемые представления инструментов |
| Делегировать агенту | Локальный и облачный поставщик выбираются в composer; облачный получатель подтверждается один раз; контекст только просматривается | Разделить в интерфейсе источники, решение об отправке и статус выполнения без добавления фиктивного режима | Контекст рабочей области, фоновый агент и opt-in доставка |
| Ревьюировать результаты | Сессии и артефакты читаются через runtime; артефакты операции могут быть опубликованы и открыты из проекта | Увязать результат, operation и источники в одном проверяемом представлении | Фоновый журнал, повторный просмотр и контроль жизненного цикла |
| Управлять инструментами и настройками | Компонент <code>ToolManager</code> отображает расширения и permissions, но текущий UI не даёт до него добраться; настройки модели и runtime доступны из модального окна | Определить доступный маршрут и безопасное подтверждение подключений | Каталог с подписью, review permissions и управляемая синхронизация |

## Продвинутый уровень

| Backbone | R1 · реализовано в 0.2 | R2 · текущий цикл | R3 · следующее |
| --- | --- | --- | --- |
| Создать проект | Core хранит манифест и служебные каталоги в папке проекта, миграция и adoption имеют отдельные операции | Проверить, что продуктовый путь не обещает шаблоны и типы, которых форма не предлагает | Контекст проекта как часть рабочей области, а не только локального пути |
| Собрать материал | Артефакты и assets различаются, копирование не перезаписывает исходный файл; провайдеры контекста читают project data | Описать границы конфиденциальности источников до расширения охвата | Opt-in синхронизация и внешние контекстные провайдеры |
| Конспектировать | Артефакт можно импортировать, прочитать и открыть по относительному пути; AI не обещан как отдельный редактор плана | Проверить provenance и источник каждого создаваемого результата | Обработка материалов в фоне с явным журналом |
| Связывать | Связи ограничены текущим проектом и типами, которые распознаёт core; глобального графа нет | Не расширять обещание до графа, пока нет реализации и модели прав | Межпроектный граф с областью видимости и подтверждаемым доступом |
| Использовать инструменты | Policy engine различает risk и permissions, задания имеют статусы и могут ожидать решения; ручной UI не подключён | Показать только реально доступные решения и безопасные деградации | Подписанный каталог расширений и фоновые инструменты с opt-in |
| Делегировать агенту | <code>approveAgentChatRun</code> продолжает ожидающий запуск с областью <code>once</code>, отмена доступна; кнопки отказа и resume в UI нет | Согласовать полный цикл решений до расширения автономности | Фоновая обработка с отдельной политикой получателя и области |
| Ревьюировать результаты | События сессии, задания и артефакты сохраняются, но отдельной стадии Execute и рабочего плана нет | Сделать проверяемыми переходы статуса и публикации | Фоновое выполнение с возобновлением и контролем побочных эффектов |
| Управлять инструментами и настройками | API поддерживает установку, обновление, откат и подключение, а текущий менеджер устанавливает пакет с <code>allowUnsigned: true</code> без выбора отдельных permissions | Установить безопасную границу разработческого режима и пользовательского каталога | Подписанный каталог, review permissions и opt-in синхронизация настроек |

## Источник фактов

R1 сверяется с компонентами desktop и runtime: <code>queryn-desktop/src/renderer</code>,
<code>queryn-desktop/src/preload/index.ts</code>, <code>queryn-desktop/src/main/index.ts</code>,
<code>queryn-runtime/src/cli.ts</code>, <code>queryn-runtime/src/runtime.ts</code> и
<code>queryn-core/packages/project</code>. R2 и R3 являются продуктовой
границей для последующих milestone-изменений и должны быть переведены в R1
только вместе с фактическим кодом и проверкой документации.
