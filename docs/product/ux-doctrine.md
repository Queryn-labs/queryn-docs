# UX-доктрина Reborn

## Информационная архитектура

```text
Workspace
  Проект
    Сессии
    Материалы и артефакты
    Подключённые инструменты
  Менеджер инструментов
  Настройки
```

Проект — главный контейнер пользовательской работы. Сессия — отдельная задача или диалог внутри проекта. Инструмент не становится верхнеуровневым «отделом» только потому, что умеет рисовать собственный экран.

## Визуальная основа

Текущий набор токенов, палитр и состояний интерфейса собран в
[визуальном референсе дизайн-системы](/design-system.png). Референс помогает
сверять рабочие поверхности и не меняет границы продукта, разрешения или
навигацию.

![Визуальный референс дизайн-системы](/design-system.png)

## Навигация после удаления глобальной боковой панели

Постоянная боковая панель удалена из оболочки приложения. Экран рабочей области уже показывает проекты и остаётся основной точкой входа в них, поэтому иконке папки отдельная замена не требуется.

Перед следующим этапом развития интерфейса нужно спроектировать самостоятельные поверхности для обязанностей, которые раньше находились в боковой панели:

- экран инструментов с каталогом, состояниями установки, подключением к проектам и запуском ручных интерфейсов;
- глобальный поиск с явно различимыми областями текущего проекта и рабочей области;
- настройки приложения и понятную точку входа в них;
- возврат из открытого проекта в рабочую область без постоянной глобальной панели.

Точки входа должны быть частью контекста соответствующего экрана. До утверждения этой информационной архитектуры не следует возвращать временную панель с набором несвязанных иконок.

## Единое поле ввода

Поле ввода живёт внутри сессии и принимает цель пользователя. В текущем
desktop-клиенте оно позволяет выбрать настроенную модель и режим памяти,
открыть preview проектного контекста и отправить запрос через `agent.chat`.
Runtime передаёт поток ответа и видимую активность tool-loop, приостанавливает
конкретную risk-операцию до approval и показывает созданные артефакты.

Текущий интерфейс не показывает отдельный структурный `AgentPlan`, не поддерживает
выбор и прикрепление артефактов из composer и не добавляет список источников в
финальный ответ. Это ограничения текущего контракта, а не скрытые состояния
пользовательского интерфейса.

Агент вызывает Operation. Он не создаёт изображение и не генерирует озвучку сам:
соответствующий Tool выполняет операцию и возвращает кандидаты артефактов.

## Контекст

По умолчанию интерфейс показывает только `Контекст · N`. Текущий popover
показывает оценку токенов, получателей, признак усечения и до восьми источников
из компактного каталога. Это preview, а не выбор или прикрепление материалов.
Полный выбор источников, прикрепление артефактов и структурированная атрибуция
источников в ответе являются будущим интерфейсным слоем. Backend не требует
постоянно держать отдельную панель контекста на экране.

## Состояния инструмента

Для пользователя Tool — одна сущность. Целевая модель разделяет состояния
установки, подключения к проекту, запуска runtime, недостающей зависимости и
деградации. Текущий renderer Tool Manager подтверждает только установленное и
подключённое расширение, список operations и объявленные manifest permissions.
Состояния запуска runtime, зависимостей, деградации, моделей, хранилища и
диагностики остаются backend-возможностями или целевым интерфейсным слоем.

## Ручная работа равноправна

Текущая ручная работа выполняется в рабочих поверхностях проекта. Runtime и API
поддерживают доступные операции, но кодовый `ToolWorkspace` пока не имеет
маршрута из `ProjectNavigator`, поэтому ручной пользовательский запуск через
него не считается поставленным потоком. Отдельный manual view для каждого
расширения пока не является общим реализованным контрактом. Целевая модель
допускает собственный manual view у Tool, чтобы пользователь мог открыть
инструмент, изменить файл, запустить операцию кнопкой или собрать артефакт
вручную без AI.

## Правила будущего фронтенда

- Не повторять на каждом экране объяснение, что такое проект.
- Не занимать рабочую область постоянной инспекцией контекста.
- Не смешивать установку, подключение и запуск инструмента в один тумблер.
- Не скрывать сетевого получателя, риск и стоимость операции.
- Не выдавать промежуточную активность tool-loop за отдельный AgentPlan.
- Не обещать источники в финальном ответе, пока для них нет отдельного поля в контракте.
- Не блокировать проект из-за отсутствия AI, OCI, модели или расширения.
- Theme меняет токены и ресурсы, но не навигацию, permissions или product logic.
