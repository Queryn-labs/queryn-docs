# Roadmap Queryn

Статусы ниже сверены с текущими исходниками `queryn-spec`, `queryn-core`,
`queryn-runtime` и `queryn-desktop`. Готово означает, что основной контракт и
рабочий путь уже присутствуют в коде. Частично означает, что базовая реализация
есть, но целевой продуктовый слой ещё не завершён.

| Фаза | Статус | Что подтверждено кодом |
| --- | --- | --- |
| 1. Нормативная основа | Готово | Формат проекта 0.2, миграция из 0.1 и ключевые продуктовые и архитектурные ADR зафиксированы в документации и спецификации. |
| 2. Доменное ядро | Готово | `@queryn/project` работает с operation-generated артефактами, сессиями, связями, обычными файлами и атомарной публикацией результатов. Нативные заметки и assets остаются обычными файлами. |
| 3. Runtime control plane | Готово | `queryn-runtime` предоставляет локальный versioned RPC, `JobManager`, `OperationRegistry`, policy, восстановление jobs и CLI для проектов, операций, контекста, артефактов, моделей и заданий. Полного headless-сценария агентного чата в CLI нет. |
| 4. Экосистема расширений | Частично | Extension Manifest v1, SDK, проверка пакетов, целостность, staging, активация, rollback, permissions и process, OCI, remote и MCP runtime присутствуют. Обязательный handshake, полный контракт платформенных зависимостей, подписанный каталог, гранулярное согласие desktop и интерфейсные вклады ещё не завершены. |
| 5. Контекст и модели | Частично | Есть контекст проекта, компактное и расширенное представление, коннекторы, встроенный каталог локальных и облачных поставщиков через OpenAI-совместимый транспорт, явный получатель и управление зависимостями моделей. Отдельные транспорты, повторное использование сеансов командных клиентов, управление локальными сервисами и подписанный публичный каталог ещё не завершены. |
| 6. Агентная оркестрация | Готово | Работает единый диалоговый tool-loop `AgentKernel` через `agent.chat` с видимой активностью, ограничениями шага и времени, per-operation approvals, provenance для опубликованных результатов и сохранением событий сессии. Отдельный AgentPlan и pipeline-движок не являются частью текущего продукта. |
| 7. Desktop integration | Частично | Electron-клиент для Windows и macOS использует typed preload bridge, локальный runtime RPC, project, settings и file services, а также рабочие поверхности проекта, материалов и сессий. Общий ToolWorkspace и ограниченный Tool Manager существуют, но универсальный manual view расширения и надёжно доступный маршрут к нему не являются завершённым рабочим путём. |
| 8. Просмотр материалов | В работе | Единая поверхность просмотра и базовой правки файлов проекта. Приоритет — текст, код, структурированные данные, PDF и изображения. Контейнерные форматы получают специализированное представление или безопасный внешний fallback. |
| 9. Ошибки и диагностика | В работе | Runtime предоставляет jobs, события и диагностический RPC. `QuerynFailure`, реестр кодов, `errorId`, сквозной `traceId`, очищенные журналы, временная расширенная диагностика и пользовательский экспорт ещё не реализованы полностью. |

## Что уже есть после backend foundation

- Компонент `Tool Manager` умеет устанавливать пакет, подключать или отключать
  расширение от проекта и показывать его operations и permissions. В текущем
  ProjectNavigator нет маршрута к этому компоненту как к завершённому экрану.
  Backend-методы обновления и отката существуют, но отдельный manual view и
  выбор grants в этом кодовом пути не реализованы.
- Настройки приложения управляют профилем, оформлением, поставщиками моделей,
  папкой проектов и диагностикой runtime.
- Локальная workspace layout хранится в настройках desktop-клиента и
  отображается через `WorkspaceLayoutRenderer` с системным виджетом проектов.

## Что остаётся следующим слоем

- подписанный публичный каталог расширений и процессы модерации;
- пользовательская синхронизация как отдельная opt-in возможность без нового
  источника истины;
- workspace-wide и computer-wide контекст с явным scope и подтверждением;
- будущий выбор и прикрепление артефактов из composer и структурированная
  атрибуция источников в финальном ответе агента;
- фоновая обработка, когда она не блокирует локальную ручную работу.
- структурированные ошибки на границах core, RPC и IPC, очищенные журналы и
  прозрачный диагностический пакет.

Эти пункты не должны менять папку проекта как источник истины. До их появления
локальные проекты, заметки, материалы, ручные операции и сессии должны оставаться
полезными без сети, облачной модели или подключённого расширения.

## Просмотрщик материалов

Просмотрщик развивается по трём уровням, которые описывают фактическое
поведение, а не отдельные режимы, которые нужно изучать пользователю.
Эти уровни нужны для планирования и тестирования, а не для вывода служебных
меток в интерфейсе.

| Уровень | Поведение | Примеры |
| --- | --- | --- |
| Встроенный просмотр | Материал разбирается внутри Queryn с поиском, копированием и навигацией | Текст, код, JSON, XML, CSV, PDF, изображения, статический HTML |
| Базовая правка | Пользователь меняет содержимое исходного файла и явно сохраняет его | Markdown, текст, код, JSON, XML, CSV, YAML, TOML, HTML, CSS |
| Внешнее открытие | Queryn показывает метаданные и передаёт файл системному приложению | Неизвестный бинарный файл, неподдержанный контейнер, повреждённый или слишком большой файл |

### Приоритеты форматов

| Приоритет | Форматы | Встроенное представление |
| --- | --- | --- |
| P0 | `md`, `txt`, `json`, `jsonl`, `csv`, `tsv`, `xml`, `yaml`, `yml`, `toml` | Текст, подсветка, поиск, номера строк, копирование, базовая правка. Для таблиц — строки и столбцы с ограниченным фрагментом |
| P0 | `html`, `htm`, `css`, `js`, `jsx`, `mjs`, `ts`, `tsx`, `py`, `java`, `c`, `h`, `cc`, `cpp`, `cxx`, `c++`, `hpp`, `cs`, `rs`, `go`, `kt`, `swift`, `dart`, `rb`, `php`, `sql`, `sh`, `bash`, `zsh`, `ps1` | Исходный текст с языком по расширению, подсветка и базовая правка. HTML дополнительно показывается как статическая страница без сценариев и сети |
| P0 | `png`, `jpg`, `jpeg`, `gif`, `webp`, `svg` | Изображение на подложке. SVG показывается как ресурс без выполнения сценариев |
| P0 | `pdf` | Локальные страницы с масштабом, перелистыванием, поиском и текстовым слоем |
| P1 | `parquet` | Схема, типы, число строк и небольшой фрагмент строк с отметкой фрагмента |
| P1 | `xlsx`, `xls` | Листы и ограниченная таблица только для чтения. Формулы не выполняются |
| P1 | `docx`, `pptx` | Приближённое извлечение текста, страниц или слайдов с явным внешним fallback |
| P1 | `ipynb` | Просмотр ячеек, исходного кода и сохранённых результатов без запуска ядра |
| Fallback | Неизвестные файлы, архивы, аудио и видео без встроенного адаптера | Метаданные, путь и открытие системным приложением |

Поддержка расширения не означает одинаковую точность отображения. Для каждого
адаптера должны быть определены размер входа, доступные действия, ограничения
и запасной путь.

Архитектурная последовательность и оценка работ зафиксированы в
[архитектуре просмотрщика](../architecture/material-viewers.md). Публичный
контракт поставщиков просмотра вводится после стабилизации встроенного P0,
единой классификации и безопасной правки.
