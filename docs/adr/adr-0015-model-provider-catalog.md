# ADR 0015: Каталог и жизненный цикл поставщиков моделей

## Статус

Принято.

## Контекст

Первичная настройка поставщика хранила только идентификатор, адрес и
необязательную учётную запись ключа. Desktop определял локального получателя по
адресу. Такой подход связывал политику передачи данных с эвристикой интерфейса,
не давал единого каталога подключений и оставлял удалённый провайдер
зарегистрированным до перезапуска runtime.

Следующие этапы предполагают отдельные транспорты, повторное использование
сеансов командных клиентов и управляемые локальные сервисы. Для них нужен
расширяемый контракт, который не объявляет ещё не реализованные способы
подключения рабочими.

## Решение

Общие DTO `ModelProviderTemplate` и `ModelProviderConfig` принадлежат
`@queryn/types`. Конфигурация явно содержит `templateId`, `type`, `endpoint` и
`recipient`. Получатель является частью сохранённого решения пользователя и не
вычисляется desktop по имени узла.

Встроенным каталогом владеет `queryn-runtime`. Он публикуется через
`model.provider.template-list` и содержит только несекретные сведения. Desktop
строит форму подключения из этого каталога через узкий preload-мост. Шаблон
может появиться в доступном каталоге только после реализации его транспорта в
runtime. На текущем этапе доступны OpenAI-совместимые локальные и облачные
подключения.

Runtime нормализует старые конфигурации без `templateId` и `recipient`, затем
проверяет соответствие шаблона, транспорта, получателя и адреса. Локальный
получатель ограничен HTTP или HTTPS на адресе обратной петли. Облачный
получатель требует внешний HTTPS-адрес.

Удаление поставщика атомарно сохраняет новый список конфигураций и снимает его
живую регистрацию. Связанный ключ удаляется из системного хранилища, только
если его учётная запись больше не используется другой конфигурацией. Каталог и
список конфигураций никогда не возвращают значение ключа.

## Последствия

Ядро контракта, runtime RPC, CLI, preload-мост и desktop используют одну форму
конфигурации. Старые локальные данные продолжают работать после нормализации.
Подмена внешнего адреса под локального получателя отклоняется до регистрации.

Подключения через сеансы Claude Code и Codex CLI, отдельные транспорты и
управление процессом llama.cpp остаются самостоятельными этапами. Для их
появления потребуется реализация транспорта и его жизненного цикла до
добавления соответствующего шаблона в доступный каталог.
