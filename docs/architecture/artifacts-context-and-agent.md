# Артефакты, контекст и агент

## Артефакты

Артефакт состоит из descriptor, одного или нескольких payloads и provenance.
Payload остается обычным файлом. Descriptor связывает результат с проектом,
сессией, inputs, operation, tool, runtime и опциональной моделью.
Для каждого input ref host сохраняет пути и SHA-256 фактически staged payloads;
если пользователь позже отредактирует исходный Markdown, provenance всё равно
описывает байты, на которых выполнялась операция.

## Контекст

Artifact type выбирает `none`, `automatic`, `declarative` или `custom` context.
Provider возвращает `compact` и `expanded` представления в заданном бюджете.
Context envelope содержит источники, freshness, sensitivity, token estimate и
признак truncation.

Обычный Markdown или файл проекта может быть источником контекста до появления
ArtifactDescriptor. В таком случае ContextSource содержит путь относительно
проекта, тип и отображаемое название. Когда материал становится входом
изменяющей операции, среда может зарегистрировать его как артефакт и закрепить
хеш входных данных в provenance.

По умолчанию индексируется только текущий проект. Внешний источник требует
отдельного connector и permission.

## Агентный цикл

Агент работает как единый диалоговый tool-loop через `agent.chat`: модель
получает системный запрос, историю сессии и схемы доступных операций, вызывает
операции и завершается текстовым ответом. Отдельный структурный `AgentPlan` и
pipeline для этого цикла не создаются.

```text
цель -> прямой ответ (общие вопросы) или точечный поиск -> чтение материалов
     -> промежуточные абзацы -> вызов operation -> observation
     -> approval при необходимости -> следующий шаг или финальный ответ
```

Агент вызывает только зарегистрированные operations. Tool выполняет работу сам.
Run имеет host-enforced лимиты `maxSteps` и `maxDurationSeconds`; опасные или
неидемпотентные операции требуют approval и не повторяются автоматически.

Системный промпт различает общие вопросы (ответ без инструментов) и вопросы о
материалах проекта (сначала поиск, затем чтение); повтор идентичного поиска
запрещён правилами. Промежуточные абзацы модели перед вызовом инструмента
сохраняются в сессию как `assistant-message` с признаком `interim` и остаются
в истории наравне с финальным ответом. Доступ к содержимому прошлых сессий —
только при включённой полной памяти текущей сессии (ADR 0011).

Наблюдения от инструментов усекаются до фиксированного бюджета символов;
операция списка материалов пагинируется по папкам, чтобы модель работала в
бюджете даже в больших проектах. Поиск по проекту устойчив к словоформам:
совпадение считается по основе термина, достаточно частичного покрытия
терминов запроса, результаты ранжируются по весам заголовка и тела.

Сетевой доступ (чтение страниц, внешние поисковые провайдеры через MCP)
проходит через policy-подтверждение и описан в ADR 0013.

Пользовательский ответ передается уведомлениями agent.output.delta; итоговая
версия один раз записывается как assistant-message. Промежуточные абзацы,
выпущенные до вызовов инструментов, записываются отдельными сообщениями и не
дублируются в финальном ответе. Текущий `ChatRun` и финальное
`assistant-message` не содержат структурированного поля `sources`. Источники
доступны в context preview и observation, если их вернула операция, а полная
атрибуция источников в итоговом ответе остаётся будущим контрактом.
