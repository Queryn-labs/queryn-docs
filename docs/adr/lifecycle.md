# Жизненный цикл ADR

ADR — неизменяемая запись о принятом архитектурном решении. Страница может
оставаться актуальной точкой ссылки даже после того, как решение заменено.

## Статусы решения

| `adrStatus` | Значение | Требование к странице |
| --- | --- | --- |
| `accepted` | Решение принято и является действующим | Новая ADR получает следующий свободный номер. |
| `superseded` | Решение заменено другой ADR | Обязательно `supersededBy` с номером существующей ADR со статусом `accepted`. |
| `rejected` | Вариант рассмотрен и отклонён | Страница остаётся в журнале как история принятия решения. |

## Стабильность пути

Файл `docs/adr/adr-NNNN-kebab-slug.md` никогда не перемещается в
`docs/archive/`. Ссылки на него, номер в журнале и обратные ссылки из кода
остаются действительными. Замена оформляется новой страницей и обновлением
фронтматтера старой ADR.

`lifecycle` относится к странице на сайте. `adrStatus` относится к решению.
Обычно ADR остаётся с `lifecycle: active` даже при
`adrStatus: superseded`, чтобы читатель мог открыть историю. Архивный баннер для
ADR не используется.

## Порядок замены

1. Создайте новую ADR со следующим свободным номером и `adrStatus: accepted`.
2. Укажите в старой ADR `adrStatus: superseded` и `supersededBy` с номером новой
   страницы.
3. Обновите журнал и ссылки в нормативных документах, которые должны вести на
   новое решение.
4. Проверьте, что обе страницы существуют, а новая ADR имеет статус
   `accepted`.

Нельзя переиспользовать номер отклонённой или заменённой ADR. Это сохраняет
историю решений проверяемой и не ломает ссылки между репозиториями.
